# Lixeira Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Excluir card, lista ou quadro passa a mandar para uma lixeira restaurável; só administrador apaga de vez.

**Architecture:** Colunas `deleted_at`/`deleted_by` em `cards`, `lists`, `boards` (migration 013). "Vivo" = card, lista e quadro sem `deleted_at`, imposto nos gates de `dependencies.py` e nos `_get_*_or_404`/listagens. Router novo `routers/trash.py` lista/restaura/apaga de vez. Audit ganha ações `lixeira`/`restaurar`; realtime converte upsert de item morto em delete.

**Tech Stack:** FastAPI async, SQLAlchemy 2, Postgres; React 19 + Tailwind v4.

**Spec:** `docs/superpowers/specs/2026-10-20-lixeira-design.md`

## Global Constraints

- Não há suíte de testes: verificação por curl contra o backend local + `npm run build`.
- **Verificar num Postgres local descartável, não no banco de produção** (a migration 013 roda no boot; não aplicar DDL de feature não revisada no banco do Easypanel). Ver "Ambiente de verificação".
- Nenhum segredo em arquivo versionado; senhas só por variável de ambiente.
- Excluir por `db.delete` (ORM) em tipos auditados; nunca bulk delete deles.
- Apagar de vez = `is_admin` (administrador), não coordenador.
- Restaurar card/lista = qualquer um que acessa o quadro; restaurar quadro = administrador.
- Changelog `2.7.0`, `kind: "novidade"`, data `2026-10-20`.

## Review Focus

1. Card na lixeira reaparecendo ao vivo em outra aba via SSE (upsert do UPDATE) → deve sumir. Task 3, passo de verificação SSE.
2. Mover card (`PATCH list_id`) ou copiar para lista na lixeira → 404. Task 1, verificação.
3. Integração re-sincronizando card de lista excluída → não ressuscita. Task 2.
4. Apagar de vez item vivo (sem passar pela lixeira) → 404. Task 4.
5. Quadro aberto excluído por outra pessoa → front sai para `/boards`, não tela branca. Task 5.

### Task 1: Modelo, migration e gates de "vivo"

**Files:**
- Create: `backend/migrations/013_lixeira.sql`
- Modify: `backend/app/models/card.py`, `list.py`, `board.py`; `backend/app/dependencies.py`; `backend/app/schemas/card.py` (`CardOut`), `list.py` (`ListOut`), `board.py` (`BoardOut`)

**Interfaces:**
- Produces: colunas `deleted_at: Mapped[datetime | None]`, `deleted_by: Mapped[int | None]` (FK `users.id`, `ondelete="SET NULL"`) em Card/List/Board; `deleted_at: datetime | None = None` em `CardOut`/`ListOut`/`BoardOut`.
- Produces em `dependencies.py`: `async def list_is_alive(list_id: int, db) -> bool` (lista e quadro dela sem `deleted_at`), `async def board_is_alive(board_id: int, db) -> bool`.
  - `require_board_access_by_board_id`: depois do 403, `board_is_alive` falso → 404 "Board não encontrado".
  - `assert_board_access_by_list_id`: depois do 403, `list_is_alive` falso → 404 "Lista não encontrada" (vale para elevado também).
  - `user_can_access_board`: falso se quadro morto.

- [ ] Escrever a migration (3×2 `ADD COLUMN IF NOT EXISTS`, FK `ON DELETE SET NULL`) e as colunas nos models.
- [ ] Gates conforme Interfaces.
- [ ] Verificar: subir ambiente local; boot aplica 013 sem erro (`schema_migrations` contém `013_lixeira.sql`); `UPDATE lists SET deleted_at=now()` numa lista → `GET /lists/{id}/cards` = 404 (admin e membro); `PATCH` card de outra lista com `list_id` dela → 404; não-membro continua 403.
- [ ] Commit `feat(lixeira): colunas deleted_at/deleted_by e gates de item vivo`.

### Task 2: Excluir vira lixeira + filtros de listagem

**Files:**
- Modify: `backend/app/routers/cards.py` (`_get_card_or_404`, `get_cards`, `update_card` select, `delete_card`), `lists.py` (`get_lists`, `_get_list_or_404`, `delete_list`, `restore_list` select), `boards.py` (`_get_board_or_404`, `list_boards`, `get_stats`, `board_snapshot`, `delete_board`, `get_archived`, `list_members`), `search.py`, `integration.py`, `attachments.py`/`reminders.py` (`_get_card_or_404`), `automations.py` (`_validate_list_in_board`, `_get_board_or_404`), `backend/app/reminders.py`

**Interfaces:**
- Consumes: colunas da Task 1.
- Produces: `delete_card`/`delete_list`/`delete_board`/`delete_external_card` setam `deleted_at=datetime.now(timezone.utc)`, `deleted_by=current_user.id` (integração: `None`) e **não** apagam Notification/Reminder/ReminderSent/Automation. `delete_list` e `delete_board` mantêm `realtime.publish_reload`.

- [ ] `_get_*_or_404` e todas as listagens acima filtram `deleted_at IS NULL` (card + lista + quadro onde a query cruza). `/stats` e `list_boards`: quadros mortos fora. Busca: `Card.deleted_at`, `ListModel.deleted_at`, `Board.deleted_at` nulos.
- [ ] Loop de lembretes: manual com card morto (card, lista ou quadro) → `fired=True` sem notificar; automático → card morto fora do select (join List/Board).
- [ ] Integração: `_get_list_or_404` exige lista e quadro vivos. `upsert_card`: se card existente "não vivo" (`card.deleted_at` ou lista/quadro morto), aplicar `_apply_updates` **sem** troca de lista (parâmetro `allow_move: bool`).
- [ ] Verificar: criar quadro/lista/card; `DELETE` card → some de `/snapshot`, `/search`, `/stats`, `/archived`; continua no banco com `deleted_by`; `DELETE` lista → lista e cards somem do snapshot; `DELETE` quadro → some de `GET /boards`, `GET /boards/{id}` = 404. Integração: upsert de card cuja lista foi excluída com `list_id` de lista viva → card continua na lista morta.
- [ ] Commit `feat(lixeira): excluir card/lista/quadro manda pra lixeira`.

### Task 4: Router da lixeira (restaurar e apagar de vez)

**Files:**
- Create: `backend/app/routers/trash.py`
- Modify: `backend/app/main.py` (incluir os dois routers)

**Interfaces:**
- Consumes: `require_board_access_by_board_id`, `get_admin_user` (`routers/auth.py`), `_card_options` não necessário.
- Produces:
  - `board_trash_router` prefixo `/boards/{board_id}/trash`, gate de router:
    `GET ""` → `{cards: [{id,title,list_id,list_title,deleted_at,deleted_by_name,comments,attachments,checklists}], lists: [{id,title,color,deleted_at,deleted_by_name,cards}]}` (mais recente primeiro; cards só de lista viva);
    `POST /cards/{card_id}/restore`, `POST /lists/{list_id}/restore` (qualquer membro; 404 se não está na lixeira desse quadro);
    `DELETE /cards/{card_id}`, `DELETE /lists/{list_id}` (`get_admin_user`; 404 se vivo).
  - `admin_trash_router` prefixo `/trash`: `GET /boards`, `POST /boards/{id}/restore`, `DELETE /boards/{id}` — todos `get_admin_user`. Item: `{id,title,color,icon,owner_name,deleted_at,deleted_by_name,lists,cards}`.
  - `deleted_by_name` nulo → `"usuário removido"`.
  - `_remove_attachment_files(card_ids, db)`: apaga `UPLOAD_DIR/<stored_name>` dos anexos desses cards (ignora ausente) — chamado **depois** do commit do purge.
- [ ] Purge replica a limpeza dos antigos `delete_card`/`delete_list`/`delete_board` (Notification, Reminder, ReminderSent, Automation) e então `db.delete`.
- [ ] Restaurar lista e quadro: `realtime.publish_reload(board_id)`.
- [ ] Verificar: membro restaura card e lista (200, voltam ao snapshot na mesma lista/posição); membro tenta apagar de vez → 403; admin apaga de vez card na lixeira → 204, linhas e arquivo de anexo somem; admin `DELETE` de card vivo pela lixeira → 404; `GET /trash/boards` como membro → 403.
- [ ] Commit `feat(lixeira): router da lixeira (restaurar e apagar de vez)`.
